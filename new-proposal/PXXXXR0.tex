\section{Motivation and Scope}

Motivation for this proposal is unchanged from that of \cite{P3037R6}: hygienic
memory management and memory safety from the use of smart pointers should also
be available during constant evaluation. Furthermore, language regularity is a
worthy goal; ensuring that \emph{where possible} a user does not encounter a
compilation error from the use of valid runtime code during constant
evaluation.

\section{Implementation}

An implementation
%by the first author,
based on libstdc++ can be found
\href{https://github.com/SCT4SP/constexpr_shared_ptr/tree/smartptr-adapt}{here}.
A comprehensive test suite is included there within
\texttt{tests/shared\_ptr\_constexpr\_tests.cpp}; alongside a standalone bash
script to run it. The proposed changes are tested within the
\texttt{inout\_tests\_voidpp\_conversion} function, and require a C++ compiler
with feature macro \texttt{\_\_cpp\_lib\_is\_within\_lifetime} defined to a
value greater than or equal to \texttt{202306L}. All tests pass with recent
Clang.
